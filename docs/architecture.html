Factory Inventory Management System

A demo full-stack app: a Vue 3 single-page app talks to a FastAPI service. The service loads JSON files into memory at startup and filters them per request. There's no database.

System architecture

Tech stack

Frontend
  • Vue 3 (Composition API)
  • vue-router 4 (HTML5 history)
  • axios for HTTP
  • Vite 8 dev server on port 3000
  • Custom SVG charts, CSS Grid layouts
  • i18n: English and Japanese (USD / JPY)
Backend
  • Python 3.11+, FastAPI
  • Pydantic v2 response validation
  • Uvicorn on port 8001
  • CORS open to all origins
  • Dependencies managed with uv
Data & tooling
  • Static JSON in server/data/
  • generate_data.py regenerates the sample data
  • pytest + FastAPI TestClient in tests/backend
  • scripts/start.sh / stop.sh

Request data flow

Example: the user picks a warehouse and a quarter on the Dashboard.

  1. Shared filter state. useFilters keeps four module-level refs (period, location, category, status). Because they live at module level, every view shares the same filter selection.
  2. View reacts. The view watches the filters, calls getCurrentFilters(), and maps location to warehouse and period to month.
  3. API client. api.js adds each non-"all" value as a query param: GET /api/dashboard/summary?warehouse=Tokyo&month=Q3-2025.
  4. In-memory filtering. FastAPI runs apply_filters (case-insensitive on category and status) and then filter_by_month, which expands a quarter into its three months and substring-matches order_date.
  5. Aggregate & validate. The endpoint computes totals (inventory value, low stock, pending orders). List endpoints are validated against their Pydantic response_model.
  6. Render. The view stores the raw response in refs (allOrders, inventoryItems) and derives chart and table data through computed properties.

Things worth knowing

Missing endpoints. api.js calls /api/tasks (GET/POST/PATCH/DELETE) and /api/purchase-orders, but main.py doesn't implement either. So the Tasks modal and purchase-order creation fail at runtime. The CreatePurchaseOrderRequest model is defined but unused.
Unrouted view. Backlog.vue exists but has no route in main.js. Backlog data reaches the UI only through the Dashboard.
State is ephemeral. The data is loaded once at import, and restarting the server resets everything. Quarter mapping is hard-coded to 2025.
